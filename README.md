# E-Commerce Order and Customer Analytics System

A DBMS capstone project: a normalized (BCNF) MySQL database for an Indian e-commerce platform. It manages customers, products, inventory, orders, payments, discounts and deliveries, and uses SQL to analyse order, payment and customer purchasing behaviour.

**What it covers:**
- ER model and BCNF schema
- DDL, DML, DCL and TCL
- Inner, outer and self joins
- Nested and correlated subqueries
- UNION, INTERSECT and EXCEPT
- 5 views and 5 indexes with EXPLAIN
- Window functions, CTEs and recursive CTEs

Every query is verified by an automated test suite of 213 checks.

---

**Website:** https://yashkantchaurasia2-alt.github.io/ecommerce-analytics-db/ is a read-only showcase with the ER diagram, every query with its result, a dashboard, and the test report.

## Tech stack
| Part | Choice | Why |
|---|---|---|
| Database | **MySQL 8.0.31+** (developed on 8.0.46) | Window functions and CTEs need 8.0; `INTERSECT` and `EXCEPT` need 8.0.31 |
| Scripts | Python 3 + `pymysql`, `python-dotenv` | Builds and tests the database; no MySQL client needed |
| Secrets | `.env` file (git-ignored) | No password is ever committed |

MySQL has no `MINUS` keyword (that is Oracle). This project uses `EXCEPT`, and also shows the `NOT EXISTS` and `LEFT JOIN … IS NULL` equivalents. MySQL also has no `FULL OUTER JOIN`, so it is emulated with `LEFT JOIN … UNION … RIGHT JOIN`.

## Setup

1. **Install MySQL 8.0.31 or newer** and make sure it is running.
   - Linux or WSL (Ubuntu):
     ```bash
     sudo service mysql start
     ```
     WSL forwards `127.0.0.1:3306` to Windows. Keep the Ubuntu terminal open while you work.
   - Your MySQL user needs `CREATE`, `DROP`, `CREATE USER`, `CREATE ROLE`, `CREATE ROUTINE` and `GRANT OPTION`, because the project creates its own users and roles.

2. **Clone the repo and install the Python packages:**
   ```bash
   git clone https://github.com/yashkantchaurasia2-alt/ecommerce-analytics-db.git
   cd ecommerce-analytics-db
   pip install -r requirements.txt
   ```

3. **Create `.env` from the template** and fill in your own values:
   ```bash
   cp .env.example .env
   ```
   ```ini
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_USER=<your mysql user>
   DB_PASSWORD=<your mysql password>
   DB_NAME=ecommerce_db
   DB_TEST_NAME=ecommerce_test
   ```
   `.env` is listed in `.gitignore`, so it is never committed. `DB_TEST_NAME` must end in `_test`; the test runner refuses to touch any other database.

## Build the database

```bash
python tools/build_main_db.py
```

This creates `DB_NAME` and runs `sql/01` … `sql/12` in order. If the database already exists, the script stops without changing anything. To rebuild from scratch, run the command below; it asks you to type `YES` before dropping the database:

```bash
python tools/build_main_db.py --reset
```

The SQL files can also be run by hand, in numeric order, from any MySQL client. Each file depends on the ones before it.

**Project users:** `db_admin`, `order_clerk` and `analyst` are created with **random** passwords, so no password appears in any file. To log in as one of them, set your own password:

```sql
ALTER USER 'analyst'@'localhost' IDENTIFIED BY '...';
```

MySQL users and roles belong to the whole server. Running the tests re-creates them for the test database, so run `build_main_db.py --reset` again if you need their grants on the main database afterwards.

## Run the tests

```bash
python tests/run_tests.py
```

The runner:
1. Drops and recreates the **test database only** (`DB_TEST_NAME`).
2. Runs every SQL file in order.
3. Checks:
   - schema: tables, keys, constraints
   - seed data: counts, variety, money reconciliation
   - **12 invalid inserts are rejected** (negative price, negative stock, invalid status, non-existent customer, …)
   - real logins as each project user, with allowed and denied actions
   - TCL: stock changes only for committed orders
   - every query result, cross-checked against an independently written query
   - views, indexes and EXPLAIN plans
   - the demo script runs cleanly and changes no data
4. Saves the result of every labelled query to `outputs/<file>.md`.
5. Prints a PASS/FAIL summary. The exit code is 0 only if every check passes.

```
==================================================
SUMMARY: 213 passed, 0 failed -> ALL PASS
==================================================
```

**Regenerating the seed data:** `sql/02_dml_seed_data.sql` is generated by `tools/generate_seed.py` with a fixed random seed, so it is identical on every run. To change the data, edit the script and run `python tools/generate_seed.py`; do not edit the SQL file by hand.

## Website

`website/` is a static site (plain HTML, CSS and JavaScript, no build step). It has six sections:
- Overview
- Schema & ER (Mermaid)
- Normalization
- Query Explorer: all 118 queries with SQL and results, filter and search
- Dashboard (Chart.js)
- Testing

It never connects to a database. `tests/run_tests.py` writes `website/data/results.json` from the freshly built test database, and leaves out the email, phone, address and reference columns. So the site holds no credentials and no personal-looking data.

- **Preview locally:**
  ```bash
  python -m http.server 8000 -d website
  ```
  Then open http://localhost:8000. Opening `index.html` directly does not work, because browsers block reading the JSON file from disk.
- **Publish:** the site is served by GitHub Pages from the `gh-pages` branch, which holds only the `website/` folder. After changing the site or re-running the tests, update it with:
  ```bash
  git subtree push --prefix website origin gh-pages
  ```
